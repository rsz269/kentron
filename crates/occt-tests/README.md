# occt-tests

Tests ported from Open CASCADE Technology (OCCT), and from other projects, run against kentron:

- `cases/`: YAML test cases (`docs/test-cases.md`), run by the `cases` test target.
- `tests/draw_*`: OCCT DRAW scripts not expressible in YAML, generated by `tools/draw2rs.py`.
- `scripts/` and `tests/draw_tcl.rs`: the DRAW scripts `tools/draw2rs.py` does not convert
  (they use Tcl: conditions, loops, procedures, ...), copied as they are and run on a Tcl
  interpreter (Molt, `src/draw/tcl.rs`), each with its group's and grid's `begin` and `end`
  files and judged by OCCT's `parse.rules`, as OCCT's own harness runs them. Those needing a
  data file that is missing, or declaring a known failure of OCCT's, are ignored.
  Sub-shapes such scripts name by `explode` order are bound where OCCT's are
  (`tcl_selectors.json`, from `tools/occt_selectors.py --tcl`), or where kentron's shape is
  a little off OCCT's, to the nearest sub-shape no other name took; and `tcl_checks.txt` adds
  checks of kentron's after a script where its own fall short (the chamfer groups' areas).
- `tests/gtest_*`: hand translations of OCCT's GTests (`GTEST_PORTING.md`).

## Expected failures

Tests of known gaps in kentron are marked as expected to fail: they pass while they fail
and fail once they pass, so that a fix shows as clearly as a regression.

- DRAW scripts are listed in `expected_failures.txt` (by OCCT script path):
  `tools/draw2rs.py` marks the YAML cases of the converted ones `expect: not_done` and
  their Rust tests `#[should_panic]`, and `tests/draw_tcl.rs` reads the list for the
  others. When one starts to pass, remove it from the list and re-run the tool.
- Hand-written tests carry their own marks: `expect: not_done` in YAML, `#[should_panic]`
  with a comment in Rust.

They take about a third of the suite's time. With `KENTRON_SKIP_EXPECTED_FAILURES=1` (or
`tools/run_tests.py --quick`) the listed scripts and `expect: not_done` cases are ignored,
and the generated `#[should_panic]` tests panic without running: a quicker run, which
does not notice one starting to pass.

## OCCT test data

Many OCCT tests read shapes from OCCT's test dataset, which is not part of this repository
(nor of OCCT's): it is an external download of about 100 MB (350 MB unpacked).

```sh
mkdir -p ~/occt-data && cd ~/occt-data
wget https://github.com/Open-Cascade-SAS/OCCT/releases/download/V7_9_0_beta1/opencascade-dataset-7.9.0.tar.xz
tar -xf opencascade-dataset-7.9.0.tar.xz && rm opencascade-dataset-7.9.0.tar.xz
```

Files are looked up by name, recursively, in the directories listed in `OCCT_TEST_DATA`
(path-list syntax), then in `~/occt-data`, `$OCCT_ROOT/data` and `~/OCCT/data`.

Without the data, YAML cases that load it are skipped (reported as ignored, with the missing
file), and generated Rust tests that need it fail with "OCCT test data file not found". Some
files OCCT's scripts use were never published; their cases are always skipped.

The tools use the same data: `tools/draw2rs.py` (`--data-dir`, default `~/occt-data`) and
`tools/occt_selectors.py`, which runs OCCT's DRAW with `CSF_TestDataPath` set to
`OCCT_TEST_DATA` or `~/occt-data`.

## BRL-CAD test files

The cases in `cases/brlcad` read STEP files from a BRL-CAD source checkout: NIST's MBE PMI
test parts (`db/nist`) and the STEP exports in `src/libbrep/tests`. They are looked up in
its `db` and `src/libbrep/tests` directories, under `BRLCAD_SRC` or else `~/brlcad`:

```sh
git clone --depth 1 https://github.com/BRL-CAD/brlcad.git ~/brlcad
```

(When the official repository is unavailable, as it was in October 2026, a mirror serves:
`https://gitverse.ru/geoceti/brlcad.git`.)

Their expected values are OCCT's reading of the same files (DRAW `stepread`, then
`sprops`/`vprops` at 1e-9 and `nbshapes`), as BRL-CAD's tests give none.

## usd-brep's tests

The cases in `cases/usd_brep` are translated from the tests of NVIDIA's
[USD BRep](https://github.com/NVIDIA-Omniverse/usd-brep), whose SMLib kernel shares no code
with OCCT: its Python tests (`source/SmPyLib/tests/test_omni_solid.py`) and its C++ API tests
(`tests/SM_API_test`, the `cpp_*.yaml` files). Each case names its source in `ported_from`.
Tests of SMLib's bindings and internals (ownership, status codes, rejected arguments, its file
formats) are left out, as OCCT's are, and none of its data files is copied. Many of its tests
only check that a result has faces: those were given closed-form values, as the case's notes
say.

`tools/crosscheck_cases.py` runs each case on three references besides kentron: SMLib itself
(`pip install usd-brep`, in a Python 3.12 of its own), OCCT through OCP, and brute force, where
no kernel takes part: the shapes as point-membership predicates, from which volume, centroid
and inertia are sampled, area counted along random lines and solids labelled on a grid.
Fillets and the like take their predicate from the case's `brute:` map, written from the
shape's definition. Expected values are closed forms where there are any; the others are
values on which brute force and the kernels agree.

```sh
tools/crosscheck_cases.py --smlib-python P --occt-python P crates/occt-tests/cases/usd_brep/*.yaml
```
